# Mo

> **自在于文件之间**
> **Move Freely Among Your Files**

Mo 是一款现代、快速、流畅且高度可定制的跨平台文件管理器。

Mo 希望重新思考文件管理器应该是什么样子：

* 更快的文件浏览
* 更流畅的交互
* 更合理的异步架构
* 更强大的文件操作
* 更自由的界面定制
* 更一致的跨平台体验

它不希望让用户适应文件管理器，而是希望文件管理器适应用户。

> 🚧 **Mo 目前处于早期开发阶段。**

---

## ✨ 特性

### 🚀 快速

Mo 从底层架构开始关注性能。

* 异步文件系统操作
* 渐进式加载
* 虚拟化文件列表
* 高效的元数据缓存
* 智能缩略图加载
* 后台任务调度
* 大目录优化

即使面对包含数万甚至更多文件的目录，也应该保持流畅响应。

---

### 🖥️ 跨平台

Mo 计划支持：

* Windows
* macOS
* Linux

Mo 不只是简单地将同一个界面运行在不同操作系统上。

在保持统一体验的同时，它会尽可能利用各个平台的原生能力，包括：

* 文件系统
* 文件监听
* 文件权限
* 系统图标
* 路径规则
* 系统窗口
* 平台特有的文件能力

---

### 🌊 流畅

文件系统操作不应该阻塞用户界面。

打开一个目录时，Mo 不会等待所有信息准备完成后才显示内容，而是根据优先级逐步加载：

```text
打开目录
   │
   ▼
读取目录项
   │
   ├──► 立即显示文件
   │
   ├──► 加载文件信息
   │
   ├──► 加载图标
   │
   └──► 后台生成缩略图
```

用户可以立即开始操作，而其他信息在后台逐渐完善。

> **界面不应该因为文件系统而停下来等待。**

键盘、鼠标和触控板都应该拥有自然、高效的交互体验。

Mo 的目标不是要求用户学习某一种操作方式，而是让不同习惯的用户都能快速完成任务。

Mo 提供从当前目录到整个文件系统的搜索能力。

#### 当前目录搜索

打开目录后，可以快速过滤当前文件列表：

```text
Documents/

report.md

    ├── 元数据

```

## 🧭 设计理念

### 速度

文件管理器最重要的体验之一就是速度。

打开目录、切换目录、搜索、选择、重命名以及文件操作，都应该尽可能快速响应。

---

### 流畅

任何后台任务都不应该轻易阻塞用户界面。

文件读取、元数据获取、缩略图生成、索引以及文件操作，都应该运行在合适的后台任务中。

---

### 简洁

功能多并不意味着界面必须复杂。

Mo 希望：

> **常用功能简单，强大功能可发现。**

用户可以直接完成日常操作，也可以在需要的时候逐渐发现更多高级能力。

---

### 自由

文件管理方式应该由用户决定。

用户可以选择：

* 怎么排列文件
* 怎么查看文件
* 怎么导航
* 怎么操作文件
* 使用什么快捷键
* 使用什么主题

Mo 提供合理的默认设置，同时允许用户进行深入定制。

---

### 原生

跨平台并不意味着所有平台都必须完全一样。

Windows、macOS 和 Linux 有不同的文件系统和系统能力。

Mo 会在统一体验和平台原生特性之间寻找平衡。

---

### 可扩展

Mo 不希望成为一个封闭的工具。

未来会探索：

* 插件
* 扩展
* 自定义命令
* 脚本
* 自动化工作流
* 第三方集成

让 Mo 能够适应更多不同的使用场景。

---

## 🏗️ 架构

Mo 采用模块化架构，将用户界面与核心文件系统能力分离。

```text
┌─────────────────────────────────────────────┐
│                     Mo                      │
├─────────────────────────────────────────────┤
│                     UI                      │
│                    GPUI                     │
├─────────────────────────────────────────────┤
│                  应用层                     │
│                                             │
│   导航 · 命令 · 状态 · 事件 · 用户交互      │
├─────────────────────────────────────────────┤
│                  核心引擎                   │
│                                             │
│ 文件系统 · 元数据 · 搜索 · 缓存 · 缩略图    │
│ 文件操作 · Watcher · 索引 · 任务调度        │
├─────────────────────────────────────────────┤
│                  平台层                     │
│                                             │
│ Windows · macOS · Linux                     │
└─────────────────────────────────────────────┘
```

核心能力尽可能与 UI 解耦。

这样文件系统、搜索、缓存、文件操作以及索引等模块可以独立演进，而不会与具体的 UI 实现产生过深的耦合。

## ⚡ 性能设计

性能是 Mo 的核心目标之一。

### 虚拟化文件列表

一个目录可能包含大量文件，因此 Mo 不会为所有文件同时创建 UI 元素。

只渲染当前可见区域以及必要的缓冲区域。

```text
┌──────────────────────────────┐
│ 文件列表                      │
├──────────────────────────────┤
│ file-001                     │
│ file-002                     │
│ file-003                     │
│ file-004                     │
│ file-005                     │
│                              │
│       当前可视区域            │
│                              │
│ file-99999                   │
└──────────────────────────────┘
```

---

### 渐进式加载

文件信息按照优先级逐步加载：

```text
目录
 │
 ▼
读取目录项
 │
 ├──► 文件名
 │
 ├──► 文件类型
 │
 ├──► 文件大小
 │
 ├──► 修改时间
 │
 ├──► 图标
 │
 └──► 缩略图
```

用户无需等待所有信息准备完成。

---

### 优先级任务

昂贵任务根据用户当前需求分配优先级。

```text
高优先级
   │
   ├── 当前可见文件
   ├── 当前选中文件
   └── 即将进入视口的文件
   │
   ▼
低优先级
   │
   └── 其他后台任务
```

让 CPU、磁盘和 IO 等有限资源优先服务用户当前正在处理的内容。

---

### 文件系统监听

Mo 将尽可能使用各个平台原生的文件系统监听能力：

```text
Windows
    └── ReadDirectoryChangesW

macOS
    └── FSEvents

Linux
    └── inotify
```

当文件系统发生变化时，只更新实际发生变化的部分，而不是重新加载整个目录。

---

## 📂 文件操作

Mo 使用独立的文件操作系统处理复制、移动、删除等任务。

```text
                 文件操作
                     │
                     ▼
                 ┌───────┐
                 │ Queue │
                 └───┬───┘
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
        Copy       Move       Delete
          │          │          │
          └──────────┼──────────┘
                     │
                     ▼
                 Progress
                     │
             ┌───────┴───────┐
             ▼               ▼
           Cancel         Complete
```

文件操作与 UI 解耦，因此即使后台正在复制大量文件，用户依然可以继续浏览和操作其他目录。

## ⌨️ 快捷键

Mo 提供完整的快捷键系统，但不会要求用户遵循某一种特定的操作习惯。

默认快捷键将尽可能符合不同平台的使用习惯。

例如：

| 快捷键            | 操作              |
| ---------------- | ---------------- |
| `↑` / `↓`        | 移动选择            |
| `←` / `→`        | 返回 / 进入目录       |
| `Enter`          | 打开              |
| `⌘⇧P`           | 命令面板            |
| `⌘F`            | 全局搜索            |
| `⌘A`            | 全选当前目录可见项      |
| `Space`          | 快速预览（Quick Look） |
| 任意字母 / 数字      | 在当前目录即时过滤       |
| `Backspace`      | 删除过滤词最后一个字符    |
| `Esc`            | 清除过滤 / 关闭面板     |
| `Delete`         | 删除选中项           |

所有快捷键最终都应该支持自定义。
